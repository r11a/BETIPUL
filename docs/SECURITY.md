# מודל אבטחה

## נכסים ואיומים עיקריים

המערכת מחזיקה מידע רפואי, מידע על חיי משפחה ופרטים מזהים. איומים מרכזיים: גניבת גיבוי, חשבון מטפל שנפרץ, הרשאת יתר לעובד משרד, חשיפת מידע בלוגים, השחתת רשומה וגיבוי שלא ניתן לשחזר.

## בקרות שמומשו ב־0.1.0

- AES‑256‑GCM לכל שדה רגיש, עם IV ותג אימות נפרדים.
- AES‑256‑GCM לחבילת הגיבוי, עם scrypt וסיסמה שאינה כלולה בחבילה.
- סיסמאות משתמשים ב־bcrypt cost 12; cookie מסוג HttpOnly ו־SameSite Strict.
- נעילה ל־15 דקות אחרי חמישה ניסיונות כניסה כושלים מאותה כתובת.
- הפרדת תפקידי admin, therapist, office, finance, supervisor ו־viewer.
- גישה לרשומות קליניות רק למטפל מוביל או למי שקיבל הרשאת clinical/supervision.
- חתימת רשומה נועלת אותה; Audit אינו ניתן לעדכון או מחיקה.
- אין תוכן קליני בפרטי Audit או בתשובות שגיאה.
- CSP, no-referrer ו־Ingress מוגבל לרשת Supervisor.

## לפני שימוש אמיתי

- הצפנת דיסק מלאה לשרת Home Assistant ולגיבויים המקומיים.
- MFA ו־VPN לגישה מחוץ לרשת; אין לבצע port forwarding ישיר.
- בדיקת חדירות, סקירת קוד ותלויות, וסריקת image.
- נוהל הצטרפות/עזיבת משתמשים וביקורת הרשאות תקופתית.
- תרגיל שחזור מתועד ועותק נוסף באתר נפרד.
- נוהל אירוע אבטחה, מיפוי ספקים, מסמך הגדרות מאגר והדרכות.
- מדיניות שמירה ומחיקה לפי סוג המקצוע והדין החל עליו.
